# Measured evidence

Store reproducible, measured evidence here as the implementation progresses:

- `plans/`: before/after `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` output.
- `benchmarks/`: repeated timings, index sizes, insert comparisons and measurement conditions.
- `quality/`: source counts, loaded counts, rejected rows by reason and reference violations.

The active source-check results are in [quality/notebook_checks.json](quality/notebook_checks.json),
generated by the shared inspection module called in notebook sections 2.1-2.7. Query plans and
performance measurements remain pending. The notebook displays and explains the
source results; raw records and credentials do not belong in committed evidence.

[quality/cleaning_report.json](quality/cleaning_report.json) records the executed
preparation stage, including row accounting, flags, post-cleaning checks, output
types and hashes. Curated CSVs and full row-level ledgers stay under the ignored
`data/stage_02/curated/olist/` tree.

[quality/nyc_source_checks.json](quality/nyc_source_checks.json) records full saved
NYC case inspection, population reference checks, input hashes, and partial
acquisition status. The 5,000-row notebook preview is separate from the 330,000
rows inspected. No source records are included in this evidence.

[quality/ddl_execution.json](quality/ddl_execution.json) records the actual initial
DDL execution in `ds_learning`: raw SQL hashes, commit status, schemas/tables,
columns and constraint details, exact row counts and post-commit verification.
The first execution created 12 tables and inserted zero data rows.

[quality/ddl_tests.json](quality/ddl_tests.json) records the database-layer checks,
including five live DDL tests in a unique temporary database. The test database
was removed; the configured analysis database was not used for fixtures.

Q1 artifacts are generated by notebook section 4.1:

- [quality/q1_monthly_category_sales.json](quality/q1_monthly_category_sales.json): all 1,273 result rows; exact BRL decimals are strings.
- [benchmarks/q1_baseline.json](benchmarks/q1_baseline.json): two warmups, seven execute/fetch samples, environment, query/result hashes, existing indexes and independent sales reconciliation.
- [plans/q1_baseline.json](plans/q1_baseline.json): separately instrumented actual EXPLAIN ANALYZE/BUFFERS plan.
- [quality/q1_tests.json](quality/q1_tests.json): seven passing checks, including six live fixture tests in a removed temporary PostgreSQL database.

The Q1 baseline exceeds the 200 ms budget. It is measured evidence for the next
optimization stage, not a claim of performance acceptance. No new indexes,
views, snapshots or other analytical questions were implemented here.

Q2 artifacts are generated by notebook section 4.2:

- [quality/q2_monthly_state_delivery.json](quality/q2_monthly_state_delivery.json): all 556 month/state groups, coverage counts and exact percentages.
- [quality/q2_late_delivery_trend.png](quality/q2_late_delivery_trend.png): purchase-cohort trends for the five highest-volume states, with sparse extreme cohorts labelled.
- [benchmarks/q2_monthly_state_delivery_baseline.json](benchmarks/q2_monthly_state_delivery_baseline.json): seven warm samples, settings, hashes and full independent Python verification.
- [plans/q2_monthly_state_delivery_baseline.json](plans/q2_monthly_state_delivery_baseline.json): actual EXPLAIN ANALYZE/BUFFERS, compiled from the single Q2 SQL statement.
- [quality/q2_tests.json](quality/q2_tests.json): nine passing Q2 tests; eight live and one offline.

All seven saved Q2 samples were below 200 ms. Q1 evidence was preserved.
The latest `quality/ddl_tests.json` records the full 41-test database suite,
including the original DDL/configuration tests plus Q1 and Q2; all passed and the
verified temporary database was removed. It supersedes the initial 25-test run.
