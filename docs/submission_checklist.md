# آزمون‌ها و وضعیت تحویل

## بخش شش

```powershell
python -m data_factory.testing
```

این فرمان Test Discovery استاندارد را با منع DNS و اتصال socket اجرا می‌کند.
فرمان عادی `python -m unittest discover -s tests -v` هم پشتیبانی می‌شود.
پاسخ‌های HTTP شبیه‌سازی و فایل‌ها در پوشهٔ موقت ساخته می‌شوند.
نتیجهٔ واقعی اجرا و تعداد تست‌ها در بخش شش `solution.ipynb` ذخیره شده است.

| موضوع | شواهد اصلی |
|---|---|
| HTTP و پاسخ ناقص | `test_http_client.py` و `test_ingestion.py`: 429، 5xx، timeout، JSON ناقص، خطای غیرقابل retry |
| قرنطینه | `test_validation.py` و `test_quality.py`: حفظ رکورد سالم، دلایل رد، آستانه، duplicate و conflict |
| ادامهٔ اجرا | `test_ingestion.py`: timestamp مساوی، فایل بدون commit، checkpoint خراب، قفل و وقفه |
| محاسبات مرزی | `test_factory.py` و `test_validation.py`: null، صفر، منفی، کبیسه، زیرثانیه و انتهای انحصاری |
| اتصال و خروجی | `test_population.py` و `test_delivery.py`: جمعیت مشترک، شمار سطر، مخرج، ماه ناقص، هش و وقفه |
| کل کارخانه و EDA | `test_factory.py` و `test_eda.py`: اجرای واقعی مراحل روی fixture آفلاین و تکرار، بودجهٔ درخواست و محاسبات تحلیل |

## اجرای افزایشی و بودجه

`--since-last-run` فقط پس از کامل‌شدن snapshot پایه مجاز است. بازهٔ جدید از انتهای
انحصاری قبلی شروع می‌شود؛ وقفه همان بازهٔ ذخیره‌شده را ادامه می‌دهد. داده‌های خام و
خروجی‌های بازهٔ جدید زیر پوشه‌های `incremental/` جدا نگهداری می‌شوند و با snapshot
قدیمی ادغام نمی‌شوند. این قابلیت پرونده‌های تازه‌ثبت‌شده را می‌گیرد؛ تغییرات بعدی
پرونده‌های قدیمی نیازمند سیاست refresh جداگانه‌اند. بازه‌های کوتاه افزایشی شرط
۳۰۰هزار رکوردِ تحویل پایه را دوباره اعمال نمی‌کنند.

در اجرای `--stage all`، manifest تعداد واقعی تلاش‌های HTTP همان اجرا را دارد؛
retry و دانلود مرجع هم شمرده می‌شوند. اجرای آفلاین `finalize` صفر درخواست دارد.
حداقل نظری برای دریافت تازه `ceil(records / batch_size) + 1` است؛ مرجع بدون cache
حداقل یک درخواست دیگر می‌خواهد. تعداد درخواست‌های تاریخیِ پیش از ابزار شمارش
موجود نیست و با این حداقل نظری جایگزین نمی‌شود.

## موارد تأییدشده و موارد باقی‌مانده

- تست‌های آفلاین، حساب رکوردها و بازتولید هش فایل‌های تحلیلی بررسی شده‌اند.
- نوت‌بوک به‌ترتیب از kernel تازه اجرا می‌شود؛ EDA چهار نمودار و یافتهٔ محاسبه‌شده دارد.
- وابستگی‌ها با نسخهٔ دقیق محیط آزمایش‌شده قفل شده‌اند. README دستور نصب و اجرا دارد.
- تاریخچهٔ محلی ۱۸ commit دارد و فایل خام در مسیرهای دادهٔ history دیده نشد.
- **دریافت کامل باقی مانده است:** ۳۳۰هزار رکورد تا ۲۵ ژوئیهٔ ۲۰۲۴ موجود است؛
  دامنهٔ انتخاب‌شده تا ابتدای ژوئیهٔ ۲۰۲۵ ادامه دارد. درخواست زنده در آماده‌سازی
  با HTTP 403 متوقف شد. پس از رفع دسترسی، `--stage all` و سپس Run All اجرا شوند.
- **شاهد Pull Request ادغام‌شده باقی مانده است:** branchهای قابلیت موجودند، اما
  PR ادغام‌شده در بررسی فعلی پیدا نشد. تغییرات باید پس از بازبینی از یک feature
  branch با توضیح به main وارد شوند؛ تاریخچهٔ قبلی نباید بازنویسی شود.

تا رفع دو مورد آخر، عنوان «تحویل کاملاً منطبق با صورت مسئله» درست نیست.
